# 个人纠错学习

入口：词库 → 个人纠错学习。默认关闭。开启后仅积累新听写；旧记录可在历史页面主动补充纠正稿。

## 收集与批量归纳

- 自动捕获围绕一次成功插入建立会话，最多观察 90 秒，间隔 750 毫秒读取；同一修改稳定 2 秒后暂存。切换焦点、新一轮听写、超时或无法定位时结束。完整输入框上下文仅在内存中用于定位，不保存到学习数据库。
- 只接受能验证插入前后对应关系的可编辑控件。安全字段、敏感应用、自身窗口、无法定位的控件及终端不自动捕获；翻译会话不进入学习队列。单条自动样本上限为 16,000 UTF-16 单位。
- 手动补充：在历史中点“补充纠正稿”，或在原应用选中改好的听写片段，按 `⌘⌥⇧L`，核对与最近一次输出的对应关系后保存。读取选区失败时使用历史入口。
- 默认累计 50 次转写归纳一次，可调整为 10–100 次。未修改记录也计数，但仅作上下文；新词必须来自用户纠正。没有任何纠正的整批不调用模型。
- 按天模式在应用运行时每分钟检查，处理本地日历今天以前的待处理记录，每个请求最多 100 条，繁忙日期分批完成。不会唤醒已退出的应用。
- 正在编辑的样本会等待会话结束；“归纳当前批次”可以主动处理不足阈值的已结束记录。每个批次只请求一次模型，不按单条消息提词。
- 请求使用当前智能处理服务及凭据，需要开启智能处理。请求有 60 秒总截止时间；输入 JSON 最大 300 KB，超过限制会保留记录并提示调小批次。失败后最多每 5 分钟自动重试，也可以手动重试。

## 学习结果

模型接收整批软件输出、用户纠正稿和已有/忽略词语，返回分类词条及对应证据。程序验证证据确实来自同一条记录的修改前后文本；未修改文本、模型猜测和格式润色不能独立支持词条。

结果进入“待确认”。可以查看原句、修改拼写后加入词库、批量加入、忽略或恢复。加入后复用已有 `preferredTerms` 通路；是否影响 ASR 由所选服务商的现有热词支持决定，智能处理同时使用词库。不会自动创建强制替换规则，也不承诺模型每次都采用词条。

## 数据与删除

纠正样本和建议保存在现有 SQLite 数据库的 `correction_samples`、`learned_terms` 表。样本关联历史 ID，记录版本用于避免请求期间的新编辑被旧结果覆盖。崩溃后未结束的采集会话会在启动时恢复为待归纳记录。

删除/清理历史会同时删除关联样本及建议中的原句证据；已经确认的词仍留在个人词库。清除学习记录会删除样本、建议和忽略状态，不删除个人词库或原转写历史。关闭学习会停止捕获和新请求，已收集记录保留。已发出的网络请求无法撤回已经发送的数据，但取消后的结果不会入库。

## 验证

`CorrectionLearningTests` 覆盖数量/日期边界、未结束会话、Unicode 定位、清空与无关修改、来源校验、重复建议、失败重试、重复点击、陈旧版本、删除后的晚到回调、清理与请求竞争及隔离设置下的中英界面渲染。

动态采集验证可运行：

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer bash scripts/verify-correction-capture.sh
```

脚本会创建独立原生文本框并运行 `CorrectionCaptureLiveTests`，调用实际插入及采集代码，检查修改后仅保存本次听写片段且不调用模型。测试宿主需要辅助功能权限；权限不足时失败，不会把未验证当作通过。正常全量测试未启动测试输入框时，此项明确跳过。脚本退出时关闭测试进程，保留临时结果供检查。

本次验证：原生全量测试通过；两项已有录音测试因测试宿主缺少麦克风权限跳过。新采集测试已尝试运行，但 XCTest 宿主缺少辅助功能权限，因此尚未完成跨进程动态验收。中英文浅色/深色界面已渲染检查。没有调用真实付费模型或上传用户历史，因此真实模型的提词质量也仍需使用后评估。

本实现优先避免误学。浏览器富文本、中文输入法长时间停留的中间态、终端及应用重建输入控件等场景仍需要实际兼容性验证；候选默认始终经过用户确认。
